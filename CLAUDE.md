# myThreads

Tisu's personal threads of daily inputs. He builds products and works in AI / data science.
Everything here is data-first: a run writes JSON, and generated artifacts are rendered from it.

Two threads, two moments of the day:

| Thread | Lands | What it is |
|---|---|---|
| **Morning Spark** | 08:00 GMT+7 | Three idea-collisions to think with |
| **Bench** | 19:00 GMT+7 | One hour of hardware curriculum to build with |

They share one front door. `index.html` at the repo root is generated by `site_index.py`,
which reads every thread's `index.json` and emits a bare list of links. Both build tools
call it at the end of a run, so whichever thread published last, the front door is right
for both. Never hand-edit `index.html`.

# Morning Spark

Three idea-collisions to start the day, delivered every morning at 08:00 (GMT+7) by a
scheduled task. This repo is the sink: the JSON in `morning-spark/data/` is the memory
that keeps the task from repeating itself, and every spark carries an out-link so the
whole story is one click away.

## Layout

```
index.html            generated by site_index.py -- the front door for every thread
.nojekyll             tells Pages to serve the files as-is, no Jekyll build
morning-spark/
  spark.py            build tool (stdlib only)
  template.html       fixed layout, tokens are [[LIKE_THIS]] -- do not edit the CSS or structure
  data/YYYY-MM-DD.json   the edition, hand-authored -- the only file you write by hand
  editions/YYYY-MM-DD.html  generated -- bilingual, carries its own language toggle
  editions/YYYY-MM-DD.txt   generated -- this is the message you send, English
  index.json          generated rollup of every spark ever sent
```

## What a spark is

A collision of two thinkers' ideas producing a fresh third thought (1 + 1 = 3), plus a
one-line "tick": a provocative question to carry all day. Three per day, three different
pairings, each tied to a builder / AI / data lens.

Tone: minimalist, Braun / Teenage-Engineering. No emoji anywhere (`spark.py` enforces this).
Every claim grounded in a real piece you actually read -- no bluffing.

dominate, and anchor at least one spark on something recently published.

## The run

0. `git fetch origin main && git checkout -B main origin/main` -- do this before anything
   else. The ledger reads the working tree, so a run that starts on any other branch sees
   an empty history, hands out an edition number already used, and repeats yesterday's
   sources. If the ledger says "no history yet" and `index.json` exists on `main`, you are
   on the wrong branch; do not curate until this is fixed.
1. `python3 morning-spark/spark.py ledger` -- gives today's date, the next edition number,
   and everything already sent. Do not reuse a piece or a pairing from it.
2. Search and fetch. Read at least one of the two pieces behind each spark so the idea is
   accurate, and keep the exact URL you read. `WebSearch` finds them; `WebFetch` has been
   returning 403 on every host, including ones that are plainly reachable, so fall back to
   `curl` rather than concluding the network is down. Only a real egress denial counts as
   blocked: check `curl -sS "$HTTPS_PROXY/__agentproxy/status"`, which names the host and
   the reason. If the pieces truly cannot be read, produce no edition and say so -- never
   assemble sparks out of search snippets.
3. Write `morning-spark/data/<today>.json` (schema below).
4. `python3 morning-spark/spark.py build` -- validates, renders all three editions, updates
   `index.json`, and regenerates the root `index.html` so today's card is linked from the
   Pages front door. It fails loudly on emoji, missing fields, or a source URL already used;
   fix the JSON and run it again. Adding the day to the site is automatic: never hand-edit
   `index.html`, just build.
5. `SendUserFile` on `morning-spark/editions/<today>.html`, status `proactive`,
   display `render`, one-line caption. Do not publish an Artifact -- the edition's durable
   home is GitHub Pages, and pushing is what deploys it.
6. Commit and push: `git add -A && git commit && git push -u origin main`.
7. Your final message is the contents of `morning-spark/editions/<today>.txt`, verbatim --
   it becomes the push notification and email. Nothing else: no preamble, no status update,
   no sign-off, no Markdown. If the run genuinely failed, the whole final message is instead
   one plain line saying what broke and whether an edition was produced.

## Data schema

```json
{
  "date": "2026-07-27",
  "edition": 1,
  "framing": "One short framing line, max 12 words.",
  "framing_vi": "Same line in Vietnamese.",
  "note": "One line on themes used, so tomorrow can avoid them. English only, never rendered.",
  "sparks": [
    {
      "title": "TWO OR THREE WORD KICKER",
      "title_vi": "KICKER IN VIETNAMESE",
      "headline": "Short punchy headline",
      "headline_vi": "Same headline in Vietnamese.",
      "a": {"who": "Ben Thompson", "what": "What his piece or framework actually argues.",
            "what_vi": "The same, in Vietnamese."},
      "b": {"who": "April Dunford", "what": "What hers argues.", "what_vi": "The same, in Vietnamese."},
      "result": "The fresh third thought, one or two lines, ending on the punchiest tail.",
      "result_vi": "The same thought in Vietnamese, also ending on its punchiest tail.",
      "result_underline": "the punchiest tail",
      "result_underline_vi": "its punchiest tail",
      "tick": "The question he carries all day.",
      "tick_vi": "The same question in Vietnamese.",
      "tick_bold": ["the key words"],
      "tick_bold_vi": ["the key words, in Vietnamese"],
      "provocation": "One or two plain sentences for the text edition.",
      "provocation_vi": "The same, in Vietnamese.",
      "source": {
        "site": "Stratechery",
        "title": "Title of the piece you read",
        "url": "https://stratechery.com/...",
        "published": "2026-07-21"
      }
    }
  ]
}
```

`result_underline` must be a substring of `result`; each `tick_bold` entry must be a
substring of `tick`. The same holds inside Vietnamese: `result_underline_vi` must be a
substring of `result_vi`, and `tick_bold_vi` of `tick_vi` -- the pairs never cross
languages. The script escapes everything and applies the markup, so never put HTML in the
JSON. Three sparks exactly. `who`, `source` and `note` are never translated.

## Vietnamese

Every authored string has a `_vi` twin and the build fails without it. The card renders
both and carries an EN / VI toggle; the choice is remembered, and a first-time visitor
whose browser is Vietnamese lands on Vietnamese.

Write it, do not translate it. The test is whether a Vietnamese product person would say
it out loud. That means keeping the English terms they actually use -- output, outcome,
retention, proxy metric, agent, ship, headcount, tagline -- instead of reaching for
Sino-Vietnamese equivalents nobody says. Match the English register: terse, punchy, plain
`bạn`, and idiom where it earns its place (`giậm chân tại chỗ`, `nhúc nhích`, `tới nơi
tới chốn`) rather than a stiff word-for-word rendering. If a Vietnamese line reads longer
and more formal than its English twin, it is wrong.

The `.txt` edition stays English, since it is the push notification and email.

## Pushing

The scheduled run commits its edition straight to `main` -- that is intended, and is the
standing permission for it. `main` is the trunk: it is the one branch that holds every
edition, so it is the only branch the ledger can dedupe against. Never let a run curate
from anywhere else, and never open a pull request for an edition.

Step 0 exists because the run cannot assume the clone lands on `main`. Check with
`git ls-remote --symref origin HEAD` if a run looks like it started on the wrong branch.

## The site

Editions live on GitHub Pages, served from `main` at the repo root. Pushing is all a run
has to do -- Pages redeploys on its own, so there is no build step to trigger, nothing to
wait on, and no Artifact to publish.

`index.html` is a bare list of links on purpose. The design lives in the dated cards; the
front door only has to be a working index, so it carries no CSS and needs no upkeep.

# Bench

A 24-week curriculum that turns a software engineer into a hardware interaction designer,
delivered one hour at a time, every evening at 19:00 (GMT+7) by a scheduled task. The
target role is Nothing's Hardware Interaction Designer posting; the eight lines of its
requirements are the rubric the whole course is scored against.

Bench is project-based. Every week is a project with a deadline, every phase is a
milestone, and every part the projects need has an order-by week attached to it. Tisu is
in Ho Chi Minh City, so the kit list carries real local shops and real lead times.

## Layout

```
bench/
  bench.py                build tool (stdlib only)
  curriculum.json         the fixed spine: 6 phases, 24 weeks, 24 projects, the kit, the shops
  template.html           the day card -- tokens are [[LIKE_THIS]], do not edit the CSS
  progress.template.html  the build log page
  kit.template.html       the supply list page
  data/NNN.json           the day, hand-authored -- the only file a run writes by hand
  logs/NNN.json           his evidence, written by `bench.py log` -- never author these
  editions/NNN.html       generated -- the card that gets sent
  editions/NNN.txt        generated -- this is the message you send
  index.json              generated rollup: every delivered day plus current state
  progress.html           generated -- 168 cells, the streak, and every line of evidence
  kit.html                generated -- what to buy, where in HCMC, and by when
```

## The shape of a day

Days are numbered 001 to 168, not dated. Six build days then a Bench Test, every week.

A build day is three blocks inside a 65-minute ceiling, and the ceiling is enforced by
`bench.py`: INTAKE (one source, actually read), BENCH (the thing he makes), LOG. A Bench
Test replaces them with SHOW, TEARDOWN and VERDICT, scores one line of the Nothing rubric,
and carries the week's result into the next one.

Every card also carries the week's project and its deadline, and `THE OBJECT`: one real
product or teardown with a single sentence on why its interaction is the way it is. The
object is not homework. It is the thing that makes the card worth opening.

`bench.py plan` names three places to hunt for tonight's object, filtered to the current
phase and rotated by day number, plus one off-web vein. They live in `curriculum.json`
under `objects`, so the run never has to reach into memory -- which is what makes the
objects go stale around week twelve. Never repeat one: `ledger` lists every object
already used. Prefer a shipped product over a concept, prefer something he could hold,
and prefer a Vietnamese object whenever one fits, because a curriculum built only on
Californian hardware teaches a narrow eye.

## The gate

**Day N cannot be built until day N-1 has a log.** `bench.py build` refuses, and that
refusal is the whole enforcement mechanism. Do not pass `--force` to get around it.

The curriculum waits for him. It never accumulates homework debt, because debt is what
makes people quit. What it does instead is report drift honestly: `day 023, calendar day
031`. Missing a day costs a number on a page, nothing more.

**Showing up and finishing are different things.** `bench.py log --partial` records a night
where he sat down and ran out of time. It keeps the streak alive, because he did the work he
had; it does not advance the day, so the next run hands him the same card again to finish.
Only drift moves. A slow night is never a failed night, and he never has to fake a log to
keep a number intact.

After three silent days `status` reports `RE-ENTRY`. The next day authored must be short,
25 minutes total, and the card says why. **After a break the work gets easier, not
harder** -- that rule is load-bearing, and it is the difference between a curriculum that
survives a bad week and one that dies in week five.

## The run

0. `git fetch origin main && git checkout -B main origin/main` -- before anything else.
   The state is read from the working tree, so a run on the wrong branch sees no logs,
   hands out a day already sent, and breaks the streak it is supposed to protect.
1. `python3 bench/bench.py status` -- the day, the streak, the drift, what is gated.
   If the previous day has no log, **deliver nothing**. The whole final message becomes a
   short unbothered nudge naming the day and the one-line command that closes it. No
   guilt, no lecture, no new material.
2. `python3 bench/bench.py plan` -- the phase, the week, the project, the deadline, the
   kit due this week, and the suggested sources. Author against this, never against memory.
3. `python3 bench/bench.py ledger` -- what has already been used. Never repeat a source or
   an object. Days already written but not yet delivered are listed; build those rather
   than writing them again.
4. Search and fetch. **Read the piece behind the day before you write about it**, and keep
   the exact URL you read. `WebFetch` has been returning 403 on hosts that are plainly
   reachable, so fall back to `curl` rather than concluding the network is down; only a
   real egress denial counts as blocked (`curl -sS "$HTTPS_PROXY/__agentproxy/status"`).
   Verify every URL resolves before it goes in the JSON, including `object.url`.
5. Write `bench/data/<NNN>.json` (schema below).
6. `python3 bench/bench.py build` -- validates, renders the card and the text, updates
   `index.json`, `progress.html`, `kit.html` and the root `index.html`. It fails loudly on
   emoji, a blown time budget, a reused source, or a gate violation. Fix the JSON and run
   it again. Never hand-edit any generated file.
7. `SendUserFile` on `bench/editions/<NNN>.html`, status `proactive`, display `render`,
   one-line caption.
8. Commit and push: `git add -A && git commit && git push -u origin main`.
9. Your final message is the contents of `bench/editions/<NNN>.txt`, verbatim -- it becomes
   the push notification and the email. Nothing else. If the run genuinely failed, the
   whole final message is one plain line saying what broke.

## Data schema

```json
{
  "day": 8,
  "kind": "build",
  "framing": "One short framing line, max 12 words.",
  "blocks": [
    {"label": "Intake", "minutes": 20, "body": "What to read or watch, and what to look for.",
     "bold": ["a phrase inside body"], "detail": ["A specific instruction.", "Another."]},
    {"label": "Bench", "minutes": 30, "body": "The thing he makes tonight. Imperative.",
     "detail": ["..."]},
    {"label": "Log", "minutes": 5, "body": "One line closing the day."}
  ],
  "source": {"site": "Apple", "title": "Exact title of the piece you read",
             "url": "https://...", "kind": "talk", "length": "24 min", "published": "2021-06-07"},
  "done_when": "The observable test that says tonight is finished.",
  "question": "The one question the log answers.",
  "object": {"name": "iPod click wheel", "why": "One sentence on why it is the way it is.",
             "url": "https://..."},
  "note": "One line for tomorrow's run: what was covered, what not to repeat. Never rendered."
}
```

Exactly three blocks. Every `bold` entry must be a substring of that block's `body`. Total
minutes must be 45 to 65 on a build day, and **the intake block must be at least as long as
`source.length`** -- a 39-minute talk does not fit in a 25-minute block. If only part of a
long piece is wanted, scope it in `length` ("28 min (stop before the SDK section)") and say
where to stop in the block detail. The number on the card must be the time it really takes. `kind` is `build`, except on days divisible by 7
where it is `bench_test` and `source` becomes optional. Set `"revisit": true` inside
`source` when a second pass at the same URL is deliberate -- the Nothing role description
is read three times, at weeks 1, 21 and 24. No HTML in the JSON; the script escapes and
marks up everything. No emoji anywhere, enforced.

## Tone

Same family as Morning Spark: minimalist, Braun / Teenage-Engineering, no emoji. Bench is
the evening counterpart, so the card is dark where Spark is paper, and shares its accent.

Write like a good workshop teacher, not a productivity app. Never congratulate him for
showing up, never use the word journey, never threaten the streak. The card states the
work, the deadline and the reason, and trusts him to be an adult about it. Dry warmth is
allowed and is usually right.

**Do not pad to fill the hour.** If a day's real work is 40 minutes, the day is 40 minutes.
The budget is a ceiling, not a quota, and filler is the fastest way to lose him.

## The kit

`bench.py kit --all` prints the whole supply list; `kit.html` is the same thing as a page
with ticks that persist in the browser. Items are filed under **the week the order must be
placed**, not the week they are used, because a part that arrives late has already cost
the project.

Local HCMC shops (Hshop, Nshop, Thế Giới IC, IC Đây Rồi, Chợ Nhật Tảo) deliver in one to
three days. Anything crossing a border does not: Watchy is ordered in week 1 for week 8,
and the PCB fab order in week 20 takes five to ten days. When a week has orders, the card
says so on the first day of that week only -- once, with time to act, and never again.

If he reports a part is unavailable or too expensive, find the substitute and say what
changes. Do not let a missing part stall a week; every project has a version that works
with less.

Both local shops publish their real catalogue as JSON -- `hshop.vn/products.json` and
`nshopvn.com/api/products?limit=5000` -- so stock and price can be checked rather than
guessed. Shopee cannot: it is client-rendered behind bot protection, and the headless
browser in this environment has no outbound network, so never quote a Shopee price.
Nshop lists far more than it stocks; when a run needs a real number, prefer Hshop.

## Pushing

The scheduled run commits straight to `main` -- that is intended, and is the standing
permission for it. `main` is the trunk: it is the one branch that holds every day and
every log, so it is the only branch the state can be read from. Never open a pull request
for a day.
